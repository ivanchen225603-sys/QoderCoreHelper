# 工单协议：拆分边界、四字段、并行策略

## 拆分边界是文件边界，不是功能边界
"实现创建接口"和"实现跳转接口"听起来是两件事，但可能都要改同一个路由
文件；"改路由层"和"改服务层"听起来是一件事的两半，却可以真正并行。
判定标准只有一个：**两张工单的 owns 有没有重叠**。
拆不开就别并行——串行两张工单，比两个 Agent 互相覆盖再花三倍时间排查
要快。`tickets.py add` 会在登记时拒绝重叠的 owns。

## 四个字段（缺一不可）
| 字段 | 语义 | 为什么 |
|------|------|--------|
| inputs | 只读这些 | 读多了会被无关信息带偏 |
| owns | 只写这些，且独占 | 写多了会覆盖别人正在做的工作 |
| requires | 前置工单全部 done | 拿半成品输入会在很远的地方失败 |
| dod | 完成判据（文件列表） | 没有判据，"做完了"只是一句自述；done 时脚本逐条核验存在 |

## 独占的两层机制
1. **账本层**（跨会话持久）：认领时查所有未完成工单的 owns，重叠即拒，
   并报出被谁占着。路径先归一化：`src/a.py` 与 `./src\a.py` 是同一个文件，
   目录与其下文件互为冲突。
2. **文件锁层**（并发竞态）：认领瞬间对每个 owns 取操作系统独占锁，
   两个进程同时认领同一文件时，慢的那个被拒绝。
缺任何一层都有洞：只靠账本拦不住并发，只靠文件锁拦不住跨会话。

## 并行策略
- 平台有独立工作副本（git worktree）：并行 Agent 物理隔离，仍要过认领检查。
- 没有：靠文件独占检查控制并行度，同一时刻活跃工单的 owns 必须互不重叠。
- 公共文件（路由表、依赖清单、配置）永远串行：单独一张工单，其他工单
  把它写进 requires。

## 生命周期命令
```
add      --id T1 --title ... --role implementer --owns ... [--inputs ...] [--requires ...] [--dod ...]
claim    --id T1 --by <子Agent署名>        # 强制独占检查 + 前置完成检查
done     --id T1                            # 逐条核验 dod 文件存在
unclaim  --id T1                            # 认领后中断/崩溃的恢复：退回待认领
next     可认领列表（前置已完、无冲突）
status / conflicts / brief
```
